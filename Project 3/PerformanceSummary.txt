Project 3 - Parallel Prime Number Sieve (Programming Project 1, p.144-145)
==========================================================================

Files
  SieveParallel.c    Parallel sieve: n/p equal portions, one process each,
                     step numbers passed down a stream pipeline 1->2->...->p
  SieveSequential.c  Textbook sequential sieve (baseline for speedup)
  SampleRuns/        Complete C* transcripts of every run in the table below

How to run (C* system, default architecture SHARED(1024))
  cstar.exe
  *OPEN SieveParallel.c
  *RUN
  32000 128          <- n and number of processes
  *EXIT

Correctness
  Every run found the correct number of primes:
    n = 100 -> 25,  n = 1000 -> 168,  n = 10000 -> 1229,  n = 32000 -> 3432
  (the n <= 1000 runs also print the full list of primes).

  Par time    = SieveParallel.c
  Speedup     = Seq time / Par time

                (total work of all processes / Par time)
  C* SPEEDUP  = end-of-run whole-program statistic printed by C*

Observations
  * Bigger arrays give much bigger speedups. With 4 processes the speedup
    rises from 3.14 (n=100) to 3.98 (n=32000); the best speedup measured is
    93.7 with 128 processes on n=32000.
  * For a fixed n, efficiency falls as p grows. Each portion shrinks, but
    every process still has to receive, forward and compute a starting point
    for every step number, and process 1 must still scan all numbers up to
    sqrt(n) by itself. That fixed per-prime cost stops shrinking.
  * The pipeline gets longer as p grows. At n=32000, going from 128 to 178
    processes makes the program slower (27191 -> 30380). The last process
    must wait for each step number to pass through 177 other processes, so
    that delay outweighs the smaller portions.
  * The largest p allowed for a given n is n / sqrt(n) = sqrt(n), because
    the first portion must contain all numbers up to sqrt(n). A larger n
    therefore allows more processes as well as more work per process.
  * The "Work ratio" is higher than the true speedup. It divides by the
    total work of the parallel program, which includes the pipeline
    overhead. The true speedup divides by the sequential program's time.
  * C* integers are 16-bit (max 32767), so n is limited to 32000 here.
